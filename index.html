Overview

A consumer-facing digital health platform delivering evidence-based patient education — articles, symptom guides, decision tools, and care videos — across 70M+ annual patient touchpoints, deployed via health system portals, EHR integrations, and health plan apps. Strong content depth, but a UX that hadn't evolved in years. I conducted the redesign as both Product Manager and Product Designer, wearing both hats across a 6-month, 3-team engagement.

The Problem +

Growing mobile traffic, rising accessibility litigation risk, and new AI capabilities created the case for a full redesign. Six things were broken, and each one had a real cost attached:

  • Mobile-first failure — 48% of traffic was mobile but the UI was desktop-designed. Navigation collapsed, text overflowed, touch targets undersized.
  • Accessibility risk — 47 WCAG 2.1 AA failures: colour contrast, broken focus states, screen reader semantics. An ADA risk and a real user blocker.
  • Findability crisis — no unified search. Users averaged 4.2 clicks to find a relevant article; the symptom checker was effectively invisible.
  • Content overload — long-form articles with no chunking. 62% abandoned before reaching actionable guidance, above the 40% norm.
  • EHR integration gaps — clinician-sent education links delivered generic content; condition-specific linking broken across 3 EHR partners.
  • No AI advantage — a vast content library but zero personalisation, zero reading-level adaptation, zero AI-assisted discovery.

Moderated Usability Sessions (not unmoderated)
Why: The audience included low-literacy and elderly users — populations that don't vocalise confusion the way tech-savvy users do. High observation mattered more than sample size.
↳ Unlocked

Accessibility Audit — automated + manual combined
Why: Automated tools catch roughly 30% of WCAG issues. Cognitive load, focus order, and ARIA live-region behaviour only surface through manual screen reader testing.
↳ Unlocked
47 failures, severity-rated — critical for sprint planning, since not all 47 could be fixed in the first pass.
Competitive Benchmark — deliberately mixed literacy levels
Why: Chose platforms at different ends of the health-literacy spectrum — NHS inform (Grade 6 targeted) vs. WebMD (expert-forward) — to see what "best in class" looked like across both ends, not just one.
↳ Unlocked
No competitor combined AI content personalisation with reading-level adaptation. That gap became the product's differentiator.

Sequencing: heuristic evaluation + analytics first (to brief stakeholders fast) → stakeholder interviews → user sessions → accessibility audit → competitive benchmark.

Information Architecture — 7 Nodes to 4 +

Card sort finding: an open card sort (Maze, 48 participants) revealed 3 distinct mental models — condition-first (62%), symptom-first (28%), topic-first (10%). No participant grouped content the way the original IA was structured; "Health Library" was recognised by only 34%. "Topics" replaced four ambiguous, overlapping nodes ("Health Library", "Wellness", "Diseases", "Conditions") with one condition-first entry and three clear sub-categories.

Five Pillars of the Solution +
  • AI-Assisted Content — GPT-powered reading-level adaptation, personalised article summaries, AI-driven recommendations based on condition, history, and literacy.
  • Unified Smart Search — single search with condition/type/literacy filters, autosuggest, contextual ranking. From 4.2 clicks to under 2.

Wireframe → Prototype → Validate +

Six key flows wireframed lo-fi first — symptom-to-content, search-to-read, EHR-link-to-article, homepage-to-article, reading-level adaptation, and save/return/progress — tested in 2 rounds (n=12) before moving to hi-fi.

  • Mid-Fi (Figma, grayscale) — clickable prototype focused on interaction patterns: search filters, accordion behaviour, reading-level toggle. Task completion: 73%, up from a 51% baseline.
  • Hi-Fi (Figma, branded) — full visual fidelity with the design system applied, 20-user validation. Task completion: 87%, 4.8/5 ease score.

  • Bottom nav reduced task time by 42% on mobile vs. a hamburger menu.
  • Unified search with autosuggest and condition filters lifted search-to-article success from 44% to 82% — patients found the right article far more often on the first try.
  • AI summary card increased full-article reads to 71% of the time.
  • Reading-level toggle used by 68% of low-literacy participants — unprompted.
  • First search filter iteration had too many options — simplified from 8 to 3.
  • EHR link flow needed 2 additional confirmation steps after clinician testing.
  • Symptom checker awareness rose to 83%, up from 19% pre-redesign.

Accessibility — WCAG 2.2, Baked In Not Bolted On +

  • Keyboard navigation — full site keyboard-operable, logical focus order, custom 3px teal focus rings, skip-to-content on every page.

Key Learnings +
  • Wearing both hats sharpens prioritisation. Being PM and PD forced ruthless decisions about what to design — every choice had a business case behind it. Less decoration, more function.
  • AI doesn't replace design — it expands the design space. Integrating AI content features meant designing for uncertainty: summaries that might be wrong, recommendations that needed guardrails. AI raised UX complexity, not lowered it.
  • Accessibility is a PM problem as much as a UX one. Getting a11y into sprint planning, audit timelines, and EHR partner sign-off was product management work — design alone doesn't ship accessible products.
  • Test with the hardest users first. Running round-1 sessions with low-literacy users meant design assumptions were challenged while it was still cheap to change them — it saved weeks of rework.

User Journey — Before & After
Problem +

The process was as risky as the label itself: personal naming conventions stood in for version control, AI flags carried no rule or confidence so reviewers closed every one, approvals moved by email reply with no audit trail, and print operators received files with no confirmation of approval status.

"I have a folder called Final. Inside it is another folder called Actually Final." — Artwork Designer
Research & Insights +
Contextual Interviews — 48 sessions Workflow & Journey Mapping — 6 maps Card Sorting — 8 participants Moderated Usability Testing — 2 rounds

Data gathered: 80+ people across three role groups, 400+ data points across two usability rounds, and a full mapping of exactly where the artwork "lost its identity" between handoffs.

Insight → Decision: Users had already workarounded the broken system into something simpler — the real workflow was invisible inside three disconnected tools.

Pivot, After Testing

The first validation prototype kept the legacy model — a binary pass/fail flag, just moved onto the canvas. In usability testing, reviewers batch-dismissed it exactly the way they'd dismissed the old flags; the location had changed but the trust problem hadn't. The card-sort data showed why: people didn't distrust flags, they distrusted flags with no reasoning attached. That reframed the fix from "make flags visible" to "make flags explain themselves" — which is what led to the three-level, rule-cited indicator (High / Review / Flag) instead of another binary pass/fail.

Key Decisions +
1. Version control
Considered: keep manual "Save As" but enforce a strict naming convention (e.g. required version tags) with training.
Rejected because: it still relies on a human following the rule under deadline pressure — which is exactly the failure already observed ("Final… Actually Final"). A convention doesn't survive contact with a rush job.
Chose: Pro Editor with system-enforced auto-versioning — every save auto-versions, timestamps, attributes, and smart-locks, removing the human step entirely. Result: 0 version conflicts post-launch.
2. AI validation
Considered: a separate validation report/checklist, shown after export — closer to how compliance checks already worked.
Rejected because: reviewers already had a separate checklist and had learned to route around it. The issue wasn't where the check lived, it was that flags carried no reasoning — moving an unexplained flag to a new location wouldn't fix that (confirmed by the pivot above).
Chose: inline, rule-cited, confidence-scored validation (High/Review/Flag) directly on the canvas, with a suggested fix attached. Result: 91% of errors caught, 3× AI action rate.
3. Approvals
Chose: one-click approve inside the system, auto-recording version, checks, and timestamp. Result: immutable audit trail by default, no separate logging step.
4. Navigation
Considered: keep the flat file list, but add stronger search and filtering.
Rejected because: search solves "find a file," not "know what stage it's in." Finn's problem — "is this definitely the right file?" — is a status problem, and better search doesn't surface status.
Chose: status-led navigation — Draft → Review → Approved → Released as the primary IA. Result: status visible at a glance, no searching required.

AI-Powered Visitor Experience
Mindtree Workplace Experience — Business Analyst + Product Designer
Overview

I designed an end-to-end workplace visitor experience system that turns check-in into a connected service moment. One check-in triggers access control, host notifications, room readiness, navigation guidance, hospitality preparation, and visitor support.

Who This Was For +
  • Visitor / Client — needs fast entry, clear guidance, and a premium hospitality experience.
  • Host / Employee — needs visit planning, tracking, room readiness, and coordination visibility.
  • Receptionist — needs reduced manual workload and better prioritisation during peak times.
The Problem

Clients experienced delays and confusion during check-in. Hosts lacked reliable tools to plan visits and arrange hospitality. Receptionists had to handle access, coordination, questions, and peak visitor traffic manually, which made premium visits feel fragmented.

Research & Insights +
Receptionist Interviews Host Discussions Client Feedback Task-Based Usability Testing

Data gathered: Logged reception overload during visitor peaks, host follow-through on food/room/access arrangements, and where clients lost confidence in the flow after check-in.

Insight → Decision: Check-in was not a single kiosk interaction — it was a chain of dependent moments across people, access, space, and hospitality. This reframed the design problem from "screen design" to system design.

Visitor Journey — Before & After
Key Decisions +
1. Check-in method
Considered: keep reception-staffed check-in but add a second desk to absorb peak-time queuing.
Rejected because: it scales headcount to fix a process problem, and doesn't touch the real bottleneck — access still had to be manually requested and granted after check-in, regardless of how fast the desk moved.
Chose: AI self check-in (face recognition, mobile number, or QR code) paired with automated access activation, so check-in and access happen in the same step.
2. On-site guidance
Considered: static wayfinding signage and printed floor maps at reception.
Rejected because: a printed map doesn't know which meeting room a specific visitor is headed to, or update when a room changes — it solves generic navigation, not this visitor's actual path.
Chose: a visitor assistant giving on-demand, personalized guidance and support tied to the visitor's actual booking.

Employee Self-Service Portal
LTIMindtree ULTIMA Works — UX Researcher & Product Designer
Overview

ULTIMA Works is the enterprise self-service portal employees use to manage timesheets, attendance, personal data, and access every internal application. I conducted a UX audit and redesign to fix tangled navigation, a desktop-only layout, and inconsistent design that were pushing employees toward the support desk instead of self-service.

The Problem

The self-service portal is how every employee manages their personal and professional information day to day — but complex navigation, a non-responsive layout, and inconsistent visual design were turning simple tasks into support tickets. Critical information like policy benefits was buried deep in the structure, hard for employees to find on their own.

Research & Insights +
Session Analysis on Existing Portal Usability Study Quantitative Survey Task Analysis

Data gathered: Observed employees performing common tasks to surface pain points and confusion, paired with survey data for measurable, quantitative validation of what the sessions showed.

Key findings:

  • Navigation issues — employees struggled to locate apps and information in a complex structure.
  • No responsive design — the portal wasn't optimized for mobile, blocking access on the go.
  • Inconsistent layout — poor visual hierarchy made the experience confusing and overwhelming.
  • Limited access to information — critical content like policy benefits was buried deep in the IA.
Key Decisions +
1. Fixing navigation
Considered: leave the existing menu structure in place and add a "Recently Used" shortcut panel to the homepage.
Rejected because: shortcuts only help for things employees have already found once — task analysis showed the real failure was first-time discovery, which a shortcut list doesn't touch.
Chose: a redesigned information architecture, with related features grouped by task instead of by system, plus keyword search for anything not in the immediate grouping.
2. Mobile access
Considered: a lightweight companion mobile app for the two or three most common tasks (timesheet, leave).
Rejected because: a second surface duplicates content and creates a new consistency problem — the audit's core finding was already an inconsistency issue, and a separate app would add another layout to keep in sync rather than fixing the original one.
Chose: a single responsive portal, one design system, functional across desktop and mobile.

Overview

A UK social housing association managing 50,000+ units had no unified platform — four operational roles each relied on spreadsheets and email chains to track KPIs and compliance. I designed a single role-adaptive platform surfacing the right information to each role from one shared data model.

The Four Roles +
  • Director of Assets — portfolio-wide KPIs, Decent Homes Standard score, cost analysis.
  • Void Manager — void pipeline by stage, re-let time vs target, rent loss exposure.
  • Compliance Officer — certificate status, overdue escalation flags, regulatory risk.
  • Repairs Manager — work order queue, SLA status, contractor assignment.
Research & Insights +
Contextual Inquiry & Shadowing — 4 roles Service Blueprinting Journey Mapping Design Thinking Workshops

Data gathered: Measured average void re-let time against target SLA, tracked how often compliance deadlines were missed due to lack of visibility, and mapped duplicate data entry happening independently across teams.

Insight → Decision: All four roles needed the same underlying data but conflicting views of it — so the decision was one shared data model with role-based dashboard routing, instead of building four separate apps.

Key Decision +
Four roles, one platform
Considered: four separate, role-specific applications, each purpose-built for its team.
Rejected because: research showed all four roles needed the same underlying data — void status, compliance status, cost — just different views of it. Four separate apps would have meant four data models to keep in sync, and the duplicate data entry the research flagged as a problem would only get worse.
Chose: one shared data model with role-based routing at login — each dashboard surfaces only the alerts, metrics, and actions relevant to that role, sharing one component library underneath.
Information Architecture
  • Role-based routing at login — hub-and-spoke model, one shared data layer
    • Director of Assets · Void Manager · Compliance Officer · Repairs Manager
  • Each dashboard — portfolio KPIs, active alerts, drill-down detail views
  • Shared component library underneath all four role views
