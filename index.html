Artwork AToM
Artwork Labelling Company / Pharma & FMCG — Principal Product Designer & UX Researcher · 18 Weeks
Overview

Regulated artwork operations ran across three disconnected products — an artwork editor, a file manager, and an early AI validation concept — stitched together with email, shared drives, and manual sign-offs. I unified them into one governed platform, cutting label review time from 6 hours to 38 minutes.

User Journey — Before & After
Problem +

The process was as risky as the label itself: personal naming conventions stood in for version control, AI flags carried no rule or confidence so reviewers closed every one, approvals moved by email reply with no audit trail, and print operators received files with no confirmation of approval status.

"I have a folder called Final. Inside it is another folder called Actually Final." — Artwork Designer
Research & Insights +
🗣️Contextual Interviews — 48 sessions 🗺️Workflow & Journey Mapping — 6 maps 🃏Card Sorting — 8 participants 🧪Moderated Usability Testing — 2 rounds

Data gathered: 80+ people across three role groups, 400+ data points across two usability rounds, and a full mapping of exactly where the artwork "lost its identity" between handoffs.

Insight → Decision: Users had already workarounded the broken system into something simpler — the real workflow was invisible inside three disconnected tools. The card-sort findings directly informed a three-level validation indicator (High / Review / Flag) instead of a binary pass/fail.

Personas & Pain Points +
A
Aria
The Designer

Relied on personal naming conventions as version control — no visibility once artwork entered the email chain.

NeededAuto-versioning and system-enforced file locking.
R
Rowan
Reviewer & Approver

Spent 4–6 hrs per label on manual checklists, ignored AI flags with no rule cited, approved by email reply.

NeededAI that shows its reasoning, and one structured workflow.
F
Finn
Print Operator

Printed from files with no print specs attached, occasionally the wrong version — "Is this definitely the right file?"

NeededOnly released, validated artwork in view with a visible audit chain.
Key Decisions +
  • Pro Editor with Auto-Versioning — every save auto-versions, timestamped, attributed, and smart-locked. Result: 0 version conflicts post-launch.
  • Inline AI Validation, On the Canvas — rule-cited, confidence-scored (High/Review/Flag) with a suggested fix, replacing unexplained flags. Result: 91% of errors caught, 3× AI action rate.
  • Unified Review + Approval Workflow — one-click approve auto-records version, checks, and timestamp. Result: immutable audit trail by default.
  • Status-Led Navigation — Draft → Review → Approved → Released became the primary IA, replacing flat file lists. Result: status visible at a glance.

Visitor Journey — Before & After
Problem +

Clients experienced delays and confusion during check-in. Hosts lacked reliable tools to plan visits and arrange hospitality. Receptionists had to handle access, coordination, questions, and peak visitor traffic manually, which made premium visits feel fragmented.

Research & Insights +
🗣️Receptionist Interviews 👥Host Discussions 💬Client Feedback 🧪Task-Based Usability Testing

Data gathered: Logged reception overload during visitor peaks, host follow-through on food/room/access arrangements, and where clients lost confidence in the flow after check-in.

Insight → Decision: Check-in was not a single kiosk interaction — it was a chain of dependent moments across people, access, space, and hospitality. This reframed the design problem from "screen design" to system design.

Users +
  • Visitor / Client — needs fast entry, clear guidance, and a premium hospitality experience.
  • Host / Employee — needs visit planning, tracking, room readiness, and coordination visibility.
  • Receptionist — needs reduced manual workload and better prioritisation during peak times.
Key Decisions +
  • AI Self Check-in — face recognition, mobile number, or QR code replaced manual reception queuing.
  • Automated Access Control — approved access activates automatically and notifies host and reception in real time.
  • Visitor Assistant — on-demand help for directions, meeting rooms, WiFi, host connection, and refreshment requests.
  • Host Dashboard — visit planning, today's visitors, meeting prep, and quick actions in one place.
Information Architecture +
Typography +

Built on the system font stack (Segoe UI on Windows kiosks, SF Pro on iOS/macOS) — chosen for zero load latency on kiosk hardware and native readability at a distance, over shipping a custom webfont.

Aa — System BoldKiosk step headers
Aa — System Semibold, largeKiosk touch targets, distance readability
Aa — System RegularHost dashboard detail text
Learnings +
  • System design was more valuable than isolated screen design — the experience depended on multiple teams acting at the right time.
  • Automation reduced cognitive load for visitors, hosts, and receptionists alike.
  • End-to-end thinking made the experience feel premium, because support continued after the check-in moment.

User Journey — Before & After
Problem +

The self-service portal is how every employee manages their personal and professional information day to day — but complex navigation, a non-responsive layout, and inconsistent visual design were turning simple tasks into support tickets. Critical information like policy benefits was buried deep in the structure, hard for employees to find on their own.

Research & Insights +
📊Session Analysis on Existing Portal 🧪Usability Study 📋Quantitative Survey 👁️Task Analysis

Data gathered: Observed employees performing common tasks to surface pain points and confusion, paired with survey data for measurable, quantitative validation of what the sessions showed.

Key findings:

  • Navigation issues — employees struggled to locate apps and information in a complex structure.
  • No responsive design — the portal wasn't optimized for mobile, blocking access on the go.
  • Inconsistent layout — poor visual hierarchy made the experience confusing and overwhelming.
  • Limited access to information — critical content like policy benefits was buried deep in the IA.
Key Decisions +
  • Simplified Information Architecture — redesigned the navigation structure and grouped related features together for faster access.
  • Mobile Optimization — built a responsive design so the portal is accessible and functional across devices.
  • Consistent Layout & Design System — a clear visual hierarchy, improved color, contrast, and use of whitespace for readability.
  • Enhanced Search — a keyword search so employees can find relevant information instantly instead of digging through menus.
Information Architecture +
Testing & Validation +

Employees were invited to perform specific tasks on the redesigned portal while I observed their interactions, collected feedback, and measured task completion time and success rates. Results were positive — the simplified navigation, mobile optimization, consistent layout, and search functionality streamlined processes and improved employee satisfaction.

Typography +

The portal runs on the system font stack (Segoe UI / SF Pro), consistent with the rest of the ULTIMA Works enterprise suite — prioritizing native rendering and readability across managed corporate devices over a custom webfont.

Aa — System BoldCard & section headers
Aa — System SemiboldLabels, links, quick actions
Aa — System RegularBody copy, table data
Key Learnings +
  • Session analysis paired with survey data gave both the "why" and the measurable "how many" — neither alone was enough to prioritize confidently.
  • Grouping by task, not by system or department, is what actually reduces navigation confusion.
  • Mobile access isn't a nice-to-have for a self-service portal — it's where a large share of quick tasks happen.

A UK social housing association managing 50,000+ units had no unified platform — four operational roles each relied on spreadsheets and email chains to track KPIs and compliance. I designed a single role-adaptive platform surfacing the right information to each role from one shared data model.

User Journey — Void Manager
Login → role dashboard→ Void pipeline by stage→ Flag overdue re-let→ Assign contractor→ Track to close
The Four Roles +
  • Director of Assets — portfolio-wide KPIs, Decent Homes Standard score, cost analysis.
  • Void Manager — void pipeline by stage, re-let time vs target, rent loss exposure.
  • Compliance Officer — certificate status, overdue escalation flags, regulatory risk.
  • Repairs Manager — work order queue, SLA status, contractor assignment.
Research & Insights +
👥Contextual Inquiry & Shadowing — 4 roles 🗺️Service Blueprinting 🧭Journey Mapping 💡Design Thinking Workshops

Data gathered: Measured average void re-let time against target SLA, tracked how often compliance deadlines were missed due to lack of visibility, and mapped duplicate data entry happening independently across teams.

Insight → Decision: All four roles needed the same underlying data but conflicting views of it — so the decision was one shared data model with role-based dashboard routing, instead of building four separate apps.

Key Decision +

Login detects role and routes to a specialised dashboard automatically — each view surfaces only the alerts, metrics, and actions relevant to that role, sharing one component library underneath.

Information Architecture +
  • Role-based routing at login — hub-and-spoke model, one shared data layer
    • Director of Assets · Void Manager · Compliance Officer · Repairs Manager
  • Each dashboard — portfolio KPIs, active alerts, drill-down detail views
  • Shared component library underneath all four role views
